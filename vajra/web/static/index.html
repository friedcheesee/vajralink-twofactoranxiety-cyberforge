How a link is scored

Every DAST proof is scored against the SAST sinks its handler can reach. A link with a proven code path and a score of 0.72 or more is confirmed deterministically. Scores from 0.48 to 0.72 go to the grey-zone arbiter; without a proven path a link is capped at 0.70 (thresholds from vajra/correlation/engine.py).

S = 0.30·call graph + 0.25·CWE + 0.15·parameter + 0.15·sink behaviour + 0.15·defence parity
VectorWeightWhat it checks
Inter-procedural call graph30%The handler reaches the sink directly, through a helper, or through an @Service it calls.
CWE taxonomy bridge25%Code-level and runtime CWEs describe the same weakness (CWE-77/78, CWE-23/22, CWE-564/89).
Parameter lineage15%The attacked HTTP parameter is an input the handler actually reads.
Sink behaviour15%The runtime evidence fits the sink API, for example a database error for a SQL call.
Defence parity and arbiter15%Guards found in code match the runtime result; grey-zone pairs go to the gpt-4o-mini arbiter, or to a strict rule without a key.
